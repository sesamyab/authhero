# Week 38 · 14 – 20 September 2026

Two new ways to reach AuthHero this week. The Management API can be exposed as
a remote MCP server, so an assistant such as Claude can read a tenant's users,
applications and logs on behalf of the administrator who signs in. And the
hosted login can run inside an iframe on your application's own site — a login
modal instead of a redirect. That second feature comes with a default that
changes for everyone: the universal login pages now refuse to be framed unless
the application has asked for it, where before any site could frame them.
Operators using the proxy package should upgrade for a fix to a host that
could get stuck answering 504 for the life of a worker.

## The Management API as an MCP server

Pass an `mcp` block to `init()` and the server answers `POST /mcp` together
with the OAuth protected-resource metadata an MCP client reads to find where
to sign in. A client such as Claude, ChatGPT's developer mode or MCP Inspector
can then read tenant settings, users, applications, connections, APIs, roles
and logs. The server is read-only.

How access works:

- **Sign-in goes through the control plane.** MCP clients identify themselves
  with a client ID metadata document, so no application has to be created for
  them up front. The administrator signs in to the control-plane tenant and
  approves the client on the consent screen.
- **Organization membership decides what you can reach.** On each call the
  caller's token is exchanged for a management token scoped to the
  control-plane organization named after the tenant, with the permissions of
  the caller's roles in that organization. The caller's own token is never
  forwarded.
- **The host decides the scope.** On the control-plane host you get every
  tenant you are a member of — call `list_tenants`, then pass `tenant_id` to
  the other tools. On a tenant's own subdomain or custom domain the tools are
  pinned to that tenant.
- **Calls go through the ordinary Management API**, so the same permission
  checks, hooks and logs apply, and secret-looking values are redacted from
  results before they reach the model.

Tokens are bound to one MCP URL: `/authorize` now accepts the `resource`
parameter and uses it as the token audience, and `/mcp` rejects any token
whose audience is not its own URL. It needs a multi-tenant deployment with a
control plane; the new MCP server page in the docs walks through the setup.

One change reaches beyond MCP: an access token's `tenant_id` claim is now
always taken from the tenant the client belongs to, rather than from the
tenant the request happened to resolve to.

## Embedded login

An application can now show the hosted login in a modal on its own site by
framing the `/u2` pages, instead of sending the user away and back.
Credentials stay on the auth origin, so scripts on the embedding page cannot
read the form.

There is no new setting. Start the login with `response_mode=web_message` and
the session is treated as embedded; the origins allowed to frame it are the
application's existing Allowed Web Origins. For an embedded session the pages:

- render compactly — no page chrome, a transparent background, the card at its
  own height — and skip the tenant's page template, which lays out a whole
  page;
- post `{ type: "authhero:resize", height }` to the parent whenever the
  height changes, so you can size the frame to each screen;
- open social and enterprise connections in a popup, because those providers
  refuse to render in a frame, and relay the result back through the frame;
- deliver errors as `authorization_response` messages, so the modal can react
  instead of showing a dead frame.

It works with `auth0-spa-js` by handing the iframe's window to
`loginWithPopup`, and the new embedded-login page in the docs covers both that
route and the plain message protocol. In the widget, the `navigate` event is
now cancelable: call `preventDefault()` on it and the widget leaves the
redirect to you.

**The default changes for everyone.** The login pages used to send no framing
headers at all, so any site could put them in a frame. Every `/u` and `/u2`
response now sends `Content-Security-Policy: frame-ancestors 'none'` and
`X-Frame-Options: DENY`; only an embedded session is allowed, and only from
the application's web origins. If something of yours framed the login pages,
it must list its origin in the application's Allowed Web Origins and start the
login with `response_mode=web_message`.

## For operators on the proxy: a host can no longer get stuck

If you run `@authhero/proxy` on Cloudflare Workers, upgrade. Both of its cache
layers, and the HTTP control-plane adapter, shared one pending lookup between
concurrent requests for the same host. On Workers a promise belongs to the
request that started it: when that request ended early — a client disconnect,
or the router's own time limit — the lookup settled neither way, and every
later request waiting on it hung. Nothing cleared it, so one cancelled request
could turn a host into a guaranteed 504 until the worker was recycled. In the
case that prompted the fix, one production host was failing nearly half its
requests while its neighbours on the same worker were fine.

Each caller now runs its own lookup. Background refreshes are still damped
during the stale window, by a timestamp rather than a shared promise. Both
cache layers also take an `upstreamTimeoutMs` deadline — 8 seconds in memory,
5 seconds in the cache-adapter layer, `0` to disable — so the configured
stale-on-error window is actually reached when an upstream stops answering,
and the HTTP adapter's timeout now covers the response body rather than only
the headers.

## Also

- **Passwordless OTP** — an application with "Passwordless OTP" ticked under
  Grant Types rejected every OTP exchange with `unauthorized_client`: the
  admin UI stored a short identifier that the token endpoint never matched.
  The token endpoint now accepts the stored value and the admin UI saves the
  correct one, so existing applications work without being re-saved.
- **Audit log** — when a social or enterprise provider returned an error to
  `/callback` on a host that does not identify the tenant — typically a user
  cancelling at the provider — the failed-login event was written without a
  tenant, and with the outbox enabled it was dropped. The tenant is now
  resolved from the login session, and the event is recorded.
- **Management API** — `GET /api/v2/resource-servers` supports checkpoint
  pagination with `from` and `take`, returning `{ resource_servers, next }`.
  Until now it ignored those parameters and returned the first page, which is
  what an Auth0 SDK or Terraform walking a long list would have seen.
- **Docs** — three corrections to last week's new sections: the rate-limiting
  intro no longer contradicts the attack-protection page, the release process
  describes the conformance job's manual trigger, and the authentication-flows
  page no longer says permissions are issued by the API.
