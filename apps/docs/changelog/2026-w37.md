# Week 37 · 7 – 13 September 2026

A quiet week with one change that matters if you are in the middle of a
migration: the bulk user import now writes a chunk at a time instead of a row
at a time, which turns a multi-day import into an afternoon — and it no longer
runs your registration hooks for imported users, which is what Auth0 does and
is a change from last week's release. The universal login page got its phone
layout repaired: a tenant's background image shows on mobile again, and the
terms link and language picker no longer vanish below 480 pixels. Client
grants gained an opt-in strict mode for scopes the API does not define,
connections can be paged by cursor, and the server starts a little faster on a
cold worker.

## Bulk import is bounded by the database, not the network

Last week's users-import job processed staged rows one at a time: up to four
existence probes, a user insert and a password insert, each awaited in turn.
Measured against a hosted PlanetScale database during a real migration that
was about 400 ms per row, almost all of it waiting on round trips — a
million-user import would have taken around 55 hours.

A chunk is now mapped in memory, each existence probe runs as one query per
field across the whole chunk, and the rows that turn out to be new users are
written with a single batched insert. A 50-row chunk goes from about 200
queries to about five.

The speedup needs an adapter that implements the new optional `createMany`
method. The kysely adapter does; drizzle and the DynamoDB adapter fall back to
the per-row write and behave as before. It also applies only to
`upsert: false` imports — the shape of a migration. An upsert changes rows
that a later row in the same chunk may itself match, so upserts still resolve
identity row by row, at the old cost.

**Two things behave differently on upgrade:**

- **Imported users no longer run registration hooks.** Pre-registration
  denial, hook metadata mutation, built-in email linking and the
  post-registration outbox event do not fire for users created by an import
  job. This matches Auth0, where a users-import job does not trigger Actions,
  and it keeps the result independent of which adapter you run. If you relied
  on registration hooks firing during an import, they no longer will.
- **A password is written with its user.** The import used to insert the user
  and then make a second call for the password, so an interrupted run could
  leave a user who could not sign in until a later sweep repaired them. Both
  now commit in one transaction.

Two fixes to the existence probe came along. Probe values were interpolated
with only their quotes escaped, so a value ending in a backslash could widen
the probe to match an unrelated user — and on an upsert job that user's row
was then overwritten with the imported values. Values are now escaped
properly. And a probe reads as many pages as it needs: none of the probed
fields is unique on its own, so several matches for one value could fill a
page and hide a match for a later value, letting an existing user be treated
as new.

## The universal login page on phones

Three things were wrong with the `/u2` login page below 480 pixels, and all
three are fixed:

- **The background image was dropped.** The page replaced the body background
  with the widget's own colour unconditionally, so a tenant's
  `theme.page_background.background_image_url` never rendered on the device
  most sign-ins come from. With a background image, the card now floats on it
  and keeps its radius and shadow; without one, the card fills the screen edge
  to edge as before.
- **A stray line split the screen.** The full-bleed layout stripped the card's
  shadow and radius but not its border, so a themed border width drew the
  card's bottom edge straight across the viewport.
- **The corner chips vanished.** The terms link and trust mark were hidden
  outright on phones, and the settings chip sat on top of the card. They now
  collapse into a footer bar pinned to the bottom of the viewport, carrying
  the terms link, the trust mark, the dark-mode toggle and the language
  picker.

If you use a custom universal-login template that wraps the widget in an
element of its own — a `<main>`, say — the first version of this fix collapsed
the card to a 243-pixel sliver on phones. That was repaired in the same week:
the card fills the width whatever markup your template puts around it.

For anyone building a login page from the widget's parts, the page chrome —
its CSS and markup — now lives in `@authhero/widget/page-chrome` rather than
being defined in the server and mirrored by hand elsewhere, and a custom
template can place the footer with an `authhero:footer` slot.

## Client grants can reject undefined scopes

Last week the server started warning when a client grant listed scopes its
resource server does not define, because those scopes are silently left out of
issued tokens. That check now runs when the grant is written:
`POST /api/v2/client-grants` and `PATCH /api/v2/client-grants/{id}` compare
the grant's scopes against the API's defined scopes.

By default nothing is rejected — the write is accepted, as Auth0 accepts it,
and a warning names the undefined scopes. A tenant that sets the
`restrict_undefined_scopes` flag gets a 400 naming them instead. A grant whose
audience matches no resource server is left alone either way, so cross-tenant
and control-plane grants keep working.

## Also

- **Management API** — `GET /api/v2/connections` supports checkpoint
  pagination: pass `from` and `take` and the response is
  `{ connections, next }` with an opaque cursor, newest first. The existing
  `page` / `per_page` mode is unchanged.
- **Cold start** — the server evaluates less code at import time: the template
  engines for emails and custom login templates are built on first use, and
  two dependencies that were being bundled twice are bundled once. The bundle
  is about 230 KB smaller and a bare import about 14% faster, with no API
  change.
- **Docs** — the last placeholder sections are real content: the release
  process, rate limiting, the error-code reference, token verification and
  custom authentication flows. Three wrong claims were corrected in passing,
  among them that the management API lives at `/api/v1/` (it is `/api/v2/`)
  and that responses are wrapped in a `{ data, error }` envelope (they are
  not). This changelog also gained its entries for weeks 35 and 36.
